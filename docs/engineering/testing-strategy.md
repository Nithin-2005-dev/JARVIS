# Testing strategy

The `unittest` suite checks deterministic replay and unique event IDs, all five service identities and scenarios, expected database/downstream fault events, monotonic per-trace times and shared payment identity, rejection of malformed structures, and JSONL parse/validation. Stage 2 covers JSON/JSONL, CSV, REST against a local HTTP server, simulated live events, malformed input, validation/normalization, deduplication, quarantine, Stage 1 sample ingestion, and a 5,000-row JSONL batch. Stage 3 covers enrichment provenance and data preservation, taxonomy and unknown types, custom rules, lifecycle/security types, late/out-of-order boundaries, window patterns across batch boundaries/services, idempotency/replay, failed stages/retry, stale claims, processing metrics, and end-to-end sample processing. All tests use local temporary SQLite and filesystem resources; no external service is contacted.
