# Testing strategy

The `unittest` suite checks deterministic replay and unique event IDs, all five service identities and scenarios, expected database/downstream fault events, monotonic per-trace times and shared payment identity, rejection of malformed structures, and JSONL parse/validation. Stage 2 covers JSON/JSONL, CSV, REST against a local HTTP server, simulated live events, malformed input, validation/normalization, deduplication, quarantine, Stage 1 sample ingestion, and a 5,000-row JSONL batch. Stage 3 covers enrichment provenance and data preservation, taxonomy and unknown types, custom rules, lifecycle/security types, late/out-of-order boundaries, window patterns across batch boundaries/services, idempotency/replay, failed stages/retry, stale claims, processing metrics, and end-to-end sample processing. Stage 4 checks trace/resource evidence, temporal and dependency rules, false-positive guards, late arrivals, merge/split, repeated execution, rollback, missing trace IDs, and a 1,200-event sparse candidate workload. All tests use local temporary SQLite and filesystem resources; no external service is contacted.

The deterministic evaluator `python3 -m payflow_simulator.correlation.evaluate --output-dir data/evaluation` writes a labeled synthetic dataset and reports pairwise incident co-membership precision/recall. Ground-truth labels are held out from the engine; results are specific to this generated scenario and do not estimate production performance.

Stage 5 RCA tests cover pool exhaustion, downstream symptoms, missing traces and metrics, malformed timestamps, duplicate investigation requests, stable snapshot retrieval, and inconclusive cases. `python3 -m payflow_simulator.rca.evaluate --output data/evaluation/stage5_rca_metrics.json --dataset-dir data/evaluation` creates a six-case synthetic evaluation with separate JSONL input and ground-truth labels, measuring top-1, top-k candidate recall, inconclusive rate, false root cause assertion rate, and small in-memory throughput. Labels are not passed into the engine. These metrics are scenario-level only and do not establish real-world accuracy. The full regression command remains `python3 -m unittest discover -s tests -v`.

Stage 6 graph and blast-radius tests are documented in [Stage 6 test strategy](../testing/test-strategy.md). The same complete test command covers direction, cycles, depth, alternative paths, validation findings, persistence/versioning, Stage 4/5 incident integration, and all earlier milestone regressions.

Stage 7 tests cover service-window feature provenance, UTC and invalid-time behavior, rolling leakage-safe baselines, cold starts, zero-variance statistical detection, deterministic Isolation Forest fit/score, late-event summaries, incident-preceding sequences, exact/approximate patterns, bounded cross-service graph joins, Stage 4/5/6 evidence linkage, rollback, immutable history, and time-ordered synthetic evaluation. Use [Stage 7 test strategy](../testing/test-strategy.md) and evaluation docs for scenario denominators and measured results.
